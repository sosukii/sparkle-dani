# Формат данных каталога

Все данные лежат в папке `data/` и читаются **только серверным слоем** (`server/repositories/`).
В `public/` JSON не попадает. Схемы и типы — в [`shared/types/product.ts`](../shared/types/product.ts) (zod).

```
data/
├── categories.json     # категории (id, slug, title, description)
├── taxonomy.json       # справочники: типы изделий, цвета, посадки, размеры, виды измерений
├── materials.json      # материалы: общие сведения для пояснения состава
├── care.json           # рекомендации по уходу (повторно используются товарами)
└── products/
    └── product-001.json   # один товар — один файл, имя файла = id товара
public/images/products/    # фотографии товаров
```

## Главное правило: `null` — это «не известно»

Сведения, которых нет, **не заполняются выдуманными значениями**. Поле равно `null` (или отсутствует), и интерфейс корректно это показывает:

| Поле | Если `null` |
| --- | --- |
| `price` | «Цена уточняется», товар нельзя положить в корзину, в сортировке по цене он в конце |
| `availability` | «Наличие уточняйте у Дани» (не «нет в наличии») |
| `composition` | блок состава скрыт или предлагает уточнить у Дани |
| `sizes` | размеры не известны (не «универсальный размер») |
| `fit` | посадка не указана или не применима |
| `care` | рекомендации по уходу не заданы |

`0` и пустая строка — это значения, а не отсутствие данных.

## Товар (`data/products/<id>.json`)

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `id` | string | да | Совпадает с именем файла: `product-001` |
| `slug` | string | да | Адрес `/product/<slug>`: `a-z`, `0-9`, дефис. Уникален |
| `title` | string | да | Название |
| `description` | string | нет | Краткое описание |
| `price` | integer \| null | нет | Цена в целых рублях; `null` — не определена |
| `category` | string | да | `id` из `categories.json` |
| `type` | string | да | `id` из `taxonomy.json → types` |
| `fit` | string \| null | нет | `id` из `taxonomy.json → fits` (обычная / оверсайз) |
| `fitNote` | string \| null | нет | Пояснение к посадке именно этой модели |
| `colors` | string[] | нет | `id` из `taxonomy.json → colors`; можно пусто |
| `composition` | `{material, percent}[]` \| null | нет | `material` из `materials.json`; `percent` — целое 1–100 или `null`, если доля не известна. Если все проценты заданы, сумма = 100 |
| `sizes` | string[] \| null | нет | `id` из `taxonomy.json → sizes`; для изделия в одном размере — `["one-size"]` |
| `measurements` | `{size, values}[]` \| null | нет | Измерения изделия в см по размерам: `{"size": "m", "values": {"chest": 52, "length": 62}}`; ключи из `taxonomy.json → measures`; размер должен быть в `sizes` |
| `model` | `{heightCm, wearsSize}` \| null | нет | Рост модели на фото и надетый размер (он должен быть в `sizes`) |
| `care` | string[] \| null | нет | `id` из `care.json` |
| `availability` | `"in_stock"` \| `"made_to_order"` \| null | нет | В наличии / под заказ / не известно |
| `stock` | integer | нет | Остаток для «в наличии». **Если не указан — лимита нет** (технический потолок — 99 шт.) |
| `leadTimeDays` | `{min, max}` | нет | Срок изготовления в днях, только для «под заказ» |
| `images` | `{src, alt, width, height, kind?, placeholder?}[]` | да, ≥1 | `src` — путь от корня сайта, `alt` — осмысленное описание, `kind` — `overview` / `detail` / `on-model`, `placeholder: true` — временная заглушка |
| `attributes` | `{label, value}[]` | нет | Дополнительные характеристики (например, длина шарфа). Показываются только заданные |
| `createdAt` | `YYYY-MM-DD` | да | Для сортировки «сначала новые» |
| `isDemo` | boolean | нет | `true` — демо-товар (для него не отдаётся Schema.org-разметка) |

Если файл товара некорректен (не проходит схему, неизвестная категория/цвет/размер/материал/уход, измерения для размера, которого нет в `sizes`, дубль id/slug), он **пропускается**, а в логе сервера появляется строка вида
`[catalog] data/products/product-007.json пропущен: ...`. Остальной каталог продолжает работать.
Если не читаются справочники, API отвечает 500 с понятным сообщением.

## Справочники

- **`materials.json`** — общие сведения о материале (`summary`). Это пояснение «что такое шерсть», а не обещание про конкретное изделие: тексты не должны утверждать, что изделие не колется, не даёт катышков, подходит для конкретной температуры и т. п. Один раз правится здесь, и обновляется везде.
- **`care.json`** — рекомендации по уходу (`label` коротко, `text` подробнее). Товар ссылается на нужные по `id`.
- **`taxonomy.json`** — `types`, `colors` (с `hex` для образца), `fits`, `sizes`, `measures`.

## Демо-товары и картинки-заглушки

В каталоге 24 демо-товара (`isDemo: true`). Они нужны, чтобы проверить все фильтры, категории и случаи «сведения не известны» (товар `product-006` специально без цены, наличия, состава, размеров и посадки). Их картинки — нейтральный узор в цвете изделия (`placeholder: true`), а не фотографии. Пересоздать: `node scripts/generate-demo-images.mjs`.

## Как добавить настоящий товар

1. Положите фото в `public/images/products/` (оригинал 1200×1500 или больше, соотношение 4:5). Адаптивные версии в `public/_img/` создаются автоматически (`npm run images`, запускается перед dev/build/generate).
2. Скопируйте любой `product-XXX.json`, поменяйте поля, поставьте `"isDemo": false` и уберите `placeholder` у картинок. Чего не знаете, оставьте `null`.
3. Новые цвета и типы добавляются в `taxonomy.json`, новая категория — в `categories.json`, новый материал — в `materials.json`.
4. `npm run test:unit` проверит целостность данных (ссылки на справочники, существование картинок, уникальность).
5. Когда все демо-товары заменены, удалите ненужные файлы товаров и картинки.

## Константы магазина — `shared/utils/site.ts`

`SITE_NAME`, `OWNER_NAME` (имя мастера на сайте), `TELEGRAM_USERNAME`, размеры страниц. Имя «Дани» меняется только здесь.
