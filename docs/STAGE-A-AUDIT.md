Статус: **на согласовании**. Код сайта на этом этапе не менялся.

Рабочий сайт на **Nuxt 4 + Vue 3 + TS strict + Tailwind 4 + Pinia**, 15 коммитов, зелёный CI и автодеплой на GitHub Pages (<https://sosukii.github.io/sparkle-dani/>).

Рекомендация: **не переписывать «весь проект с нуля»**, а выполнить «пересборку интерфейса поверх сохранённой инженерной основы». Всё, что связано с дизайном, контентом и демо-данными, удаляем целиком (без мусора). Репозиторий, пайплайны, тестовую обвязку, поиск и корзину сохраняем: они решают те же задачи, что в ТЗ, и уже проверены.

## 2. Макеты `design ok`: что берём и что нет

**Берём как референс:**
- общая тёмная палитра (сохраняем без изменений, см. §7);
- структура каталога: левая панель фильтров, активные фильтры-чипы со снятием по одному, «Сбросить все», пагинация;
- страница товара: галерея с миниатюрами, выбор посадки, блок характеристик справа, «Связаться с Даней в Telegram (уточнить мерки)»;
- мобильный каталог: фильтры в выдвижной панели;
- Bodoni Moda для логотипа и крупных заголовков.

**Не берём (противоречит ТЗ §2.3, §4, §9):**

| Что в макете | Почему нет |
| --- | --- |
| «Бесплатная доставка по РФ от 20 000 ₽», «Примерка курьером» | Неподтверждённые условия доставки (§9) |
| «Пожизненный сервис / ремонт», «Страхование груза», «Сертификат гильдии» | Неподтверждённые обещания (§9) |
| «Est. 1894», «Архивный выпуск № 44 — тираж 10 экземпляров», «Лот», «Предпродажа», «Лимитка 6 шт», «Ограниченная серия» | Выдуманная история и ложная срочность/дефицит (§2.3) |
| Адреса в Санкт-Петербурге и Москве | Не подтверждены |
| «Среднее время ответа 20–40 минут» | Неподтверждённое обещание |
| Имя автора «Даниил Ноктерн» и биография | Нельзя выдумывать имя и детали автора (§9) |
| Термо-рейтинг «Level III, +2…−18 °C», «Паспорт крафтового полотна», «5-gauge», «Беби-альпака Сури» | Нельзя выводить свойства из состава (§7.1) и выдумывать состав |
| «Закрытый клуб» с подпиской на рассылку | Нет такой функции и нет бэкенда |
| Избранное (сердце) и счётчики, переключатель RUB/EUR | Нет в сценарии. Элементы, которые выглядят интерактивными, но ничего не делают (§4) |
| Нижняя мобильная навигация «Архив / Ателье / Патреон» | Лишние разделы, расходится с десктопом (§8) |
| Мелкий капс-моно текст с низким контрастом | Доступность (§4.1, §11) |
| Водяные знаки «FINAL — Product — Desktop» и текст внутри картинок | Артефакты экспорта. Фото в макетах — ИИ-генерация: **нельзя** использовать как фото реальных изделий (§5.3) |
| Мобильная главная с «ленивым» декоративным hero и теснящимся текстом | Расходится с десктопом, плохо читается |

## 3. Карта пользовательского пути

Первый вход → каталог → товар → «подойдёт ли» → условия → Telegram.

| Шаг | Вопрос покупателя | Видно сразу | По запросу | Действие / что дальше |
| --- | --- | --- | --- | --- |
| Главная | Что это? Где смотреть? | Одна фраза «авторский вязаный трикотаж», кнопка «Смотреть каталог», 3–4 категории, 4–6 свежих изделий | Как купить (кратко, 3 шага) | → каталог |
| Каталог | Что есть? Сколько? Как отфильтровать? | Сетка, фото+название+цена+наличие, счётчик, поиск | Фильтры (панель / drawer), сортировка | чипы фильтров, «Сбросить», пустое состояние с выходом |
| Товар | Как выглядит? Из чего? Какой размер? Как ухаживать? | Галерея, название, цена, размеры/варианты, 3–4 ключевых характеристики, главная кнопка | «Что означает состав?» (раскрытие), «Как выбрать размер?» (диалог), уход, подробнее о материале | выбор → кнопка → объяснение шага |
| Покупка | Что произойдёт после кнопки? | Подпись «Откроется Telegram с сообщением для Дани. Оплаты на сайте нет» | Состав сообщения до отправки | → Telegram (с названием, ссылкой и размером) |
| Вопрос | Как спросить? | Постоянная ссылка «Написать Дане» | — | Telegram с контекстом товара |

## 4. Информационные компоненты (общая система)

`SpecRow` (характеристика, знает «неизвестно» ≠ «нет»), `Explainer` (пояснение рядом с характеристикой, раскрытие), `MaterialInfo` (общие сведения о материале из справочника), `SizeHelper` (диалог выбора размера + мерки), `CareSummary`, `OrderStep` (что произойдёт после кнопки), `AskDanya` (Telegram с контекстом), `MissingData` (нейтральное состояние).

Справочник материалов и ухода вынесен в `data/materials.json`, товары ссылаются на него по ключу. Тексты общих пояснений не дублируются. Любой текст пояснения проходит по §7.1: без обещаний про тепло, колючесть, катышки.

## 5. Структура страниц

`/` · `/catalog` (+ `?category=`, `?q=`) · `/product/[slug]` · `/search` · `/cart` · `/info/materials` (материалы и уход, одна страница с якорями) · `/info/sizes` (размеры и мерки) · `/delivery` (покупка и доставка: пока только подтверждённое) · `/about` (о бренде, коротко) · `404`.

Убираем: «Свой заказ» как отдельная страница (по макетам и ТЗ это сообщение Дане, превращаем в блок «Не нашли свой размер? Напишите Дане»).

## 6. Адаптивность

Одна сетка и общие компоненты. 1280 / 768 / 390 как контрольные, дополнительно 360, 430, 820, 1024. Фильтры: колонка на ≥1024, drawer ниже. Галерея: миниатюры слева на desktop, полоса снизу на mobile. Основная кнопка на mobile закрепляется внизу экрана товара. Навигация: одно меню на всех ширинах (в drawer на mobile), без отдельной нижней панели.

## 7. Палитра: остаётся как в утверждённых макетах

Макеты `design ok` служат **только ориентиром** (структура и удачные решения). Цветовая гамма сохраняется ровно та же, что в `design ok/nocturne_atelier/DESIGN.md`. Новых цветов не вводим, только раскладываем существующие по ролям:

| Роль | Цвет из макета |
| --- | --- |
| Основной фон | `#210F03` |
| Поверхность (карточки, панели) | `#2A1708`, приподнятая `#2F1B0B` / `#3B2515` |
| Основной текст | `#FFDCC5` |
| Вторичный текст | `#DAC1B9` |
| Границы | `#54433D` (обводка `#A28C85` для полей) |
| Основной акцент (кнопка покупки) | `#743014` Spiced Wine на тексте `#FA9975`/`#FFDCC5`, ссылки `#FFB59A` |
| Второй акцент (метки, детали) | `#E8D1A7` Golden Batter, `#9D9167` Olive Harvest |
| Ошибка | `#FFB4AB` на `#93000A` |

Если какая-то пара из этой палитры не даёт контраст AA (≥4.5:1), то подбираем **ближайший оттенок из той же палитры**, а не новый цвет; такие случаи перечислю в отчёте. Контраст проверяется скриптом в тестах. Bodoni Moda только в логотипе и крупных заголовках, Inter для интерфейса.

| Данные | Почему важно | Пока что |

## 9. UX-проблемы текущего сайта

1. Контент и бренд не соответствуют ТЗ (Мари, игрушки и бисер).
2. Светлая палитра против утверждённого тёмного направления.
3. На карточке товара нет пояснений к характеристикам (§2.2), нет помощи с размером, нет блока ухода и «что произойдёт после кнопки».
4. «Свой заказ» отдельной страницей дублирует Telegram-сценарий.
5. Контакт Telegram временный (`sosukii`).
6. Фильтры привязаны к демо-таксономии (фандомы, тепло), не к трикотажу.

## 11. Вопросы, требующие решения

1. **Название и имя мастера в UI:** «NOCTURNE» и «Даня» везде? (В коде сейчас «Sparkle Dani»/«Мари».)
2. **Telegram Дани** — username.
3. **Реальные данные и фото** — есть ли они уже, или первый релиз идёт с пустым/демо-каталогом, помеченным как «скоро»? Моё предложение: на первом релизе показывать 6–8 нейтральных товаров-примеров, явно помеченных внутренним флагом `isDemo` и не публикуемых в sitemap, пока нет реальных.
4. **Корзина:** оставляем (список → Telegram с составом) или убираем в пользу одной кнопки «Написать Дане» на товаре? Рекомендую оставить: вещей мало, но заказ нескольких — частый сценарий.
5. **Страница «Свой заказ»** превращаем в блок в каталоге/товаре (рекомендую).
